    Installation¶

    Python 3.12, the acquisition engine as a submodule, and a lock file. Nothing needs a compiler.

    Requirements¶
    Python 3.12, not negotiable: the pinned numpy and scipy require it, and scipy is not optional.
    Acquisition engine A git submodule under tools/, pinned to a commit. Fetched with the repository; nothing to install separately.
    SoapySDR Optional. See below.
    SDR hardware Not needed. The tool reads recordings.

    Install¶

    git submodule update --init --recursive
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -c requirements-lock.txt -e ".[dev]"

    Use -c requirements-lock.txt. The project declares only loose lower bounds, which is right for a library but lets machines drift: a fresh resolve once pulled versions the suite had never run on. The lock file is the set the suite passes on, verified by installing from it into a clean venv. The working set is 29 packages, all available as wheels.

    The submodule ships prebuilt Windows binaries, so on Windows there is normally no build step. On Linux, the acquisition engine's binaries and library have to be built from the submodule's source.

    Keep the submodule on its pinned commit¶

    The engine's commit goes into every store's cache key and every report's provenance, as a constant. It is not verified at run time. A different commit still measures, but every report then claims the pinned one regardless, which makes its provenance record false. And the test suite skips entirely, without failing, if the submodule is not on the pinned commit. A run that is all s is not a passing run.

    git submodule update --init --recursive checks out the pinned commit. Run it again after pulling.

    With no package index¶

    Build a wheelhouse on a connected machine and carry it (about 141 MB):

    pip download -d wheelhouse -r requirements-lock.txt setuptools wheel
pip install --no-index --find-links wheelhouse -c requirements-lock.txt -e ".[dev]"

    pip download .[dev] alone is not enough

    It fetches the runtime dependencies but not the build backend, so the editable install on the target dies with pip subprocess to install build dependencies did not run successfully: pip reaches for setuptools while --no-index forbids it. That is why setuptools wheel are on the download line. It failed exactly this way before the line was fixed.

    SoapySDR (optional)¶

    The acquisition engine's tracking binaries link SoapySDR eagerly, and will not start without it, even for file replay with no hardware attached. Its acquisition binary, which is the only one the measurement path uses, is unaffected.

    So the measurement path does not need it. Its absence costs four determinism tests, which skip, and the enrichment path, nothing else.

    If you want it on Windows, one conda environment of about 166 MB is enough:

    conda create -y -p "$USERPROFILE/radioconda" --override-channels -c conda-forge soapysdr

    %USERPROFILE%\radioconda\Library\bin is one of the two places the tool searches, and it puts it on the child process's path itself, so there is no PATH edit and no activation. The other is wherever GNSS_VSA_SOAPY_DIR points. On Linux, put the library anywhere the dynamic linker looks.

    Check the install¶

    python -m pytest -q
    Result Meaning
    everything passes, 1 skipped Healthy. The skip is a PVT test that needs ephemeris the bundled short captures cannot supply.
    5 skipped SoapySDR is absent. That is the documented cost, not a failure.
    everything skipped The submodule is not on the pinned commit. See above.

    On a machine with many cores, the suite caps BLAS threads before numpy is imported, which is the only moment the setting has any effect. Uncapped on a 48-core box it does not finish.
