    Architecture¶

    Use an acquisition engine to find each signal, then measure it with an open-loop correlator, and difference the results across elements and carriers.

    The governing idea: acquisition supplies side information¶

    Acquisition supplies side information; it does not supply the measurement.

    The expensive operation in any GNSS receiver is the 2D search over code phase × Doppler. For L1 C/A at 12 MHz that is about 12 000 code-phase bins × 21 Doppler bins, ≈ 2.5 × 10⁵ cells, roughly 18 bits. Acquisition narrows it to a quarter sample and ±60 Hz: one cell. Those 18 bits are the side information.

    What is left after the pointer arrives is not a search. It is local estimation: a handful of taps around a known peak and a fine frequency fit. That is why the correlator is a few hundred lines rather than a receiver. It never acquires, never tests hypotheses, never locks.

    Acquisition

    Coarse code phase and Doppler

    Where to look. Never any reported metric.

    The instrument

    Every reported metric

    Fine code offset, residual frequency, carrier phase, C/N0. Never a search, lock or hypothesis.

    The pointer is a starting point, not a result. Every number in a report is measured at tolerances two orders of magnitude tighter than the pointer that located it. A tracking receiver's estimates of the same quantities are closed-loop: the DLL and PLL smooth a fractional-delay staircase with their loop response, so the structure this project exists to detect is the structure the loop removes.

    The pointer verifies itself, so it does not need to be trusted. If it points wrong, the measurement says so: the peak is not where it was claimed, the early/late imbalance blows up, C/N0 collapses. That is why the pointing implementation can be swapped freely.

    Three sources of side information¶

    Side information reaches an estimator from exactly three places, and the design takes a different stance on each:

    From Examples Stance
    the signal the pointer; on long captures, nav data → ephemeris → PVT, TOW, az/el Use freely, but screen it. Only the pointer verifies itself.
    the estimator's own past DLL/PLL loop state Refuse. This, and only this, is what open-loop means here.
    the user the commanded scenario: trajectory, element geometry, expected offsets Refuse by default (that is blind), but it is a choice.

    Open-loop and blind are independent axes, not synonyms. A conventional receiver is blind and closed-loop: it uses no scenario truth and still runs a DLL/PLL.

    Keeping rows 1 and 3 apart is what makes the higher-layer test possible: decode what the signal says, compare it with what the user commanded, and the residual is the device's error. It is not circular, because the two sources are independent. The first real recording ran this once: a 120 s simulator capture decoded its own ephemeris and solved a position 2.01 m from the scenario's declared one.

    One open-loop path, for every source¶

    ANY capture → acquire (pointer) → open-loop re-correlate → series → detectors → report
                                                             ↑
        [only if long enough] tracking → logs → nav / PVT / az-el as ENRICHMENT

    The measurement is always open-loop, for every source. Capture length changes the statistics available, never the estimator, so a metric measured on a 200 ms recording is directly comparable with the same metric on a five-minute run.

    This is forced, not preferred. The tracking receiver logs its state once per second, so a 200 ms capture yields a single record, before lock. Navigation decode needs 6 s. On recorders that capture only 100–200 ms per shot (a hardware property, on part of the fleet), the log-based pipeline yields nothing. So the enrichment tier (tracking, nav, PVT) is optional forever, and nothing load-bearing is built on it.

    The re-correlator¶

    What open-loop re-correlation provides that a tracking loop structurally cannot:

    • Feedback-free phase. No PLL/DLL smoothing.
    • Any coherent integration length, so time resolution versus sensitivity is a knob rather than an inherited log cadence.
    • Any tap geometry, so the correlation shape is measurable, not merely its peak.
    • Full-depth samples. It runs against the original IQ, never a requantized file, so requantization affects only the pointer.
    • Common-mode cancellation. The same replica across elements makes any replica error common mode, cancelling exactly in inter-element differences.

    The replica uses the acquisition engine's own code generation, so the definitions are identical to what was acquired. The fractional code offset is applied as a band-limited delay, an exact phase ramp on a base whose sample-snapping error has been removed. The code discriminator's slope is measured on each series from four probe taps around the early/late pair, not assumed from an ideal triangle, which was wrong by 2.1× on E1B.

    The pipeline and the store¶

    Stage Does Re-run when
    spectrum PSD and front-end checks, from the IQ input changes
    acquire pointer: Doppler and code phase per satellite input changes
    correlate open-loop re-correlation → complex series integration or tap geometry changes
    diff align and difference elements correlate changes
    analyze detectors → metrics a new metric is added
    report HTML presentation changes

    A new detector re-runs analyze alone, in seconds, never correlate and never acquisition. Work is content-addressed on (input hash, effective arguments, acquisition engine commit, tool version). A stage's output replaces its partition, one per (element, carrier), rather than merging into it, so a re-run that finds less leaves less behind. Merging on a key once turned 10 acquired signals into 31 measured ones.

    Built to be extended¶

    • Generic series. A series is one element's observable or an inter-element difference, and the detectors cannot tell which. This is what makes N = 1 and N = 16 the same codebase.
    • The library is the API. The CLI is a thin shell; a GUI, if one is ever justified, would be an analysis GUI over the archive.
    • Capture losslessly now, decide what it means later. The store keeps the raw series, so a metric added later runs over captures already measured.
    • Do not resample to force a common rate. A resampler is a fractional-delay interpolation filter: precisely the artefact class the tool exists to measure.
