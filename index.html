    Measure the signal,
    not the loop¶

    A vector signal analyzer for GNSS simulators and signal generators. It uses an acquisition engine only to find each satellite, then measures every number itself with an open-loop correlator, so the delay steps, interpolator ripple and phase jumps that a receiver's tracking loops smooth away stay in the measurement.

    What it does¶

    • Open-loop, every number

      Acquisition supplies a pointer, meaning where to look. Code offset, carrier phase, Doppler and C/N0 are then measured by the tool's own correlator against the original samples. It runs no DLL, no PLL and keeps no loop state.

    • One element or sixteen

      A capture is a grid of N elements × M carriers. A single-element capture is a first-class case: the tool's first real finding was visible only in a single-element series, because differencing cancelled it.

    • Spectrum without a lock

      PSD, DC and LO leakage, IQ imbalance, spurs and clipping, straight from the IQ. This stage needs no satellite, so it still answers when nothing acquires.

    • Staircases and ripples

      quantize finds a delay snapped to a grid; ripple finds the smooth periodic error an interpolator leaves, which lies on no grid. step and stability cover jumps, drift and Allan deviation.

    • Inter-element differences

      Elements are joined on (carrier, satellite, signal, epoch), never zipped by position. The code-period wrap is undone and the carrier-phase origin removed, and that origin is reported. The same detectors run over the differences unchanged.

    • Says when it could not run

      Every detector writes a row whether it ran or not. A row reading too_short with a reason is designed output. validate names what a capture can feed before anything is measured.

    • A store you can query

      Parquet on disk, DuckDB on top. Work is content-addressed on inputs, arguments, the acquisition engine's commit and the tool's version, so retuning a detector takes seconds and never re-correlates.

    • One file to share

      A self-contained HTML report, with no server and nothing else to install. Its Notes and assumptions section comes before any number it qualifies.

    • A library first

      The CLI is a thin shell over the library, and a test enforces it. Every subcommand is a plain function call with the same arguments.

    Every reported number

    It runs no search and no lock and tests no hypotheses, which is why the correlator can stay a few hundred lines.

    What it has found¶

    Example cases from measuring a software GNSS simulator under development. They include defects in the generator and errors the tool found in itself.

    • Half a sample early

      Every satellite arrived exactly half a sample early (12.2 m) at any whole number of samples per chip. A receiver would have put it all into its clock bias. Three independent checks pinned it on the generator; after its fix, the error read below 0.0013 samples.

      A half-sample timing bias

    • Late at every power of two

      The code jumped late by ~0.22 samples (5.4 m) whenever elapsed time crossed 2^k seconds, each burst twice as long as the last. The cause was a rounding tie at exact chip boundaries; after the fix, 7 events became 0.

      Power-of-two code jumps

    • The first finding was ours

      A ripple at one cycle per sample was first attributed to the generator. It came from the tool's own replica, which could not place a chip edge between samples. The attribution was retracted and the measurement kept.

      The instrument's own errors

    Not there yet

    The enrichment path (tracking, navigation decode and PVT joined onto the series, for long captures) is part built. It will bring checks on the navigation data itself: subframe integrity per element, and a bit-exact comparison across elements. The carrier packer and inter-carrier differencing, the 16-element runner, and residuals against a declared expected model are designed but not started. refine assumes a constant Doppler, which leaves −aT²/12 of code bias on long captures. Status and roadmap lists exactly what is built.
